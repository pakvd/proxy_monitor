# Мониторинг прокси

Один сервер сам проверяет все прокси: открывает `ip:port` с логином и паролем и делает через них HTTP GET. Отдельные агенты на фермах не нужны, пока порты прокси доступны с машины мониторинга — тем же входом, что и у клиента.

Путь проверки: монитор → порт 3proxy → VLAN модема → LTE → URL проверки. Закрытый порт значит, что не слушает сам прокси. Таймаут после соединения обычно значит, что модем или канал не пускает трафик. `407` — неверный логин или пароль. В ответе виден внешний IP модема и его смена.

## Деплой на прод

Стенд — Linux-сервер, с которого открываются порты прокси. На нём нужен Docker с командой `docker compose`.

```bash
sudo mkdir -p /opt/proxy-monitor
sudo chown "$USER" /opt/proxy-monitor
git clone https://github.com/pakvd/proxy_monitor.git /opt/proxy-monitor
cd /opt/proxy-monitor
cp .env.example .env
chmod 600 .env
```

Сгенерируйте ключ базы и вставьте его в `.env` вместе с паролем панели и белым списком:

```bash
openssl rand -base64 32
```

```bash
MONITOR_PASSWORD=длинный-пароль-панели
MONITOR_SECRET=вывод-команды-выше
MONITOR_ALLOWLIST=203.0.113.10,10.8.0.0/24
MONITOR_HTTPS=1
MONITOR_COOKIE_SECURE=1
MONITOR_TLS_NAMES=203.0.113.50
```

`MONITOR_TLS_NAMES` — IP или DNS-имя этого сервера. Оно попадает в самоподписанный сертификат. Несколько значений пишутся через запятую.

`MONITOR_PASSWORD` — вход в панель. `MONITOR_ALLOWLIST` — адреса администраторов или сеть VPN, через запятую. `MONITOR_SECRET` шифрует пароли прокси в базе. Сохраните его отдельно от сервера: без этой строки база после переноса не расшифруется, и проверки не смогут войти в прокси. Файл `.env` в git не попадает.

Откройте TCP 8080 только с этих адресов. Если входящие соединения на сервере по умолчанию закрыты:

```bash
sudo ufw allow from 203.0.113.10 to any port 8080 proto tcp
```

Запуск и проверка:

```bash
docker compose up -d --build
curl -kfsS https://127.0.0.1:8080/api/health
```

При первом запуске контейнер сам создаёт сертификат в `data/certs/`. Ключ остаётся на сервере и в git не попадает. Панель: `https://АДРЕС_СЕРВЕРА:8080`. Браузер один раз предупредит, что сертификат выпущен самим сервером: подтвердите исключение для этого адреса. Дальше сессия идёт по HTTPS.

Если браузер получает отказ, в журнале есть строка `закрыт доступ с …`. Этот адрес добавьте в `MONITOR_ALLOWLIST` и выполните `docker compose up -d`. На Docker Desktop локальный браузер часто виден как `192.168.65.1`.

После смены `MONITOR_TLS_NAMES` достаточно `docker compose up -d`: сертификат выпустится заново. Каталог `data/certs` удаляют только если нужно сменить ключ при тех же именах.

Обновление уже установленного стенда:

```bash
cd /opt/proxy-monitor
git pull
```

В `.env` добавьте `MONITOR_HTTPS=1`, `MONITOR_COOKIE_SECURE=1` и `MONITOR_TLS_NAMES` с IP или именем сервера. Затем:

```bash
docker compose up -d --build
```

Откройте `https://АДРЕС_СЕРВЕРА:8080` и подтвердите сертификат. Порт остаётся 8080, отдельное правило файрвола не нужно.

Копия данных. Остановите контейнер, сохраните каталог `data/` и строку `MONITOR_SECRET`, затем запустите снова:

```bash
docker compose stop
tar -C /opt/proxy-monitor -czf ~/proxy-monitor-data.tgz data
docker compose start
```

`docker compose down` каталог `data/` не удаляет.

Сертификат выпускает сам контейнер, отдельный nginx для HTTPS не нужен. Если перед панелью всё же стоит свой прокси, приложение видит адрес этого прокси, чаще `127.0.0.1`, а не адрес браузера. Тогда в `MONITOR_ALLOWLIST` ставят адрес прокси, а снаружи доступ ограничивает файрвол. В этом случае в `.env` можно поставить `MONITOR_HTTPS=0`, чтобы шифрование осталось на внешнем прокси.

Панель можно оставить только на localhost и открывать туннелем. В `docker-compose.yml` замените публикацию порта на `127.0.0.1:8080:8080`, затем с рабочей машины:

```bash
ssh -L 8080:127.0.0.1:8080 user@сервер
```

Адрес, который после этого появится в журнале отказа, добавьте в белый список.

## Запуск локально

Контейнер слушает порт 8080. База с паролями прокси лежит на хосте в каталоге `data/`.

```bash
cp .env.example .env
```

В `.env` задайте `MONITOR_PASSWORD` и белый список, например `MONITOR_ALLOWLIST=203.0.113.10,10.8.0.0/24`.

```bash
docker compose up -d --build
```

Панель: https://127.0.0.1:8080

Остановить: `docker compose down`. Каталог `data/` при этом сохраняется.

Без Docker нужен Python 3.11+. На macOS `python3` часто указывает на 3.9, тогда берите `python3.12` или `./run.sh`.

## Защита панели

Пароль и белый список читаются только из окружения, в настройках панели их поменять нельзя.

Белый список — это адреса, с которых можно открыть панель: отдельные IP и сети через запятую. Чужой адрес получает отказ. Список смотрит на прямое подключение, заголовок `X-Forwarded-For` не учитывается. Проверка живости `/api/health` остаётся открытой, чтобы Docker мог проверять контейнер.

Пять неверных паролей с одного адреса блокируют вход на 15 минут. Сессия живёт 7 дней и по HTTPS не уходит в обычный HTTP.

Порт 8080 лучше не публиковать в интернет. Домашний адрес или VPN в белом списке закрывают панель сильнее, чем один пароль.

## Смена IP модемов

Интервал задаётся в панели, в блоке «Модемы». По умолчанию диапазоны меняются каждые 30 минут: сначала `1,7,20`, затем `1,3,20`. На время смены и перезагрузки простой не записывается как падение. Если все прокси модема молчат дольше указанного числа минут, служба на ферме перезагружает модем и повторяет попытку не раньше чем через 15 минут.

На мониторе в `.env` задайте общий ключ:

```bash
MONITOR_AGENT_TOKEN=$(openssl rand -hex 24)
```

После правки `.env` выполните `docker compose up -d`.

На каждой ферме API модема уже лежит локально. Туда же кладётся служба. Один агент обходит все модемы этого сервера: для `192.168.1.1`–`192.168.50.1` в `agent.json` достаточно `modem_from`, `modem_to` и общего логина. На каждый адрес он вызывает `netmode.py` отдельно. Перезагрузка — та же команда, что одна строка ручного цикла: `python3 /home/pak/huawei-api/examples/reboot.py http://admin:пароль@192.168.N.1`. Запускается только молчащий модем, остальные адреса на сервере не трогаются. Имя фермы совпадает с колонкой `address`. В колонке `name` у прокси пишется IP его модема, например `192.168.12.1`. Пароль модема остаётся только в `agent.json`, в том же виде, что в bash после кавычек.

```bash
sudo mkdir -p /etc/proxy-monitor
sudo cp agent/agent.json.example /etc/proxy-monitor/agent.json
sudo cp agent/farm_agent.py /home/pak/huawei-api/farm_agent.py
sudo cp agent/farm-agent.service /etc/systemd/system/farm-agent.service
sudo chmod 600 /etc/proxy-monitor/agent.json
```

В `agent.json` укажите адрес монитора, `MONITOR_AGENT_TOKEN`, имя фермы и адрес каждого модема. Затем:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now farm-agent
```

Когда в шапке панели ферма появится «на связи», удалите старые строки crontab со `netmode.py`. Пока крон остаётся, он продолжит переключать диапазоны каждые пять минут параллельно со службой.

Кнопка «Сменить диапазоны сейчас» просит все подключённые фермы сменить набор на ближайшем опросе, не дожидаясь интервала.

## Excel

Первая строка — заголовки. Обязательны `ip` и `port`. Дальше `login`, `password`, `address`. По желанию `name` (модем или VLAN) и `protocol` (`http`, `https`, `socks5`, `socks4`).

Те же колонки можно назвать по-русски: `порт`, `логин`, `пароль`, `адрес`. Шаблон скачивается из панели.

`address` — имя сервера или площадки. По нему панель группирует список, например `farm-01`.

Если прокси перезапускаются по расписанию, проверка не считает первый закрытый порт падением: она ждёт до 30 секунд и повторяет запрос. Время ожидания меняется в настройках панели. Ноль отключает повтор.

Внешние IP копятся за всё время работы базы. Одинаковый адрес на соседних проверках — это один выход. Повтор считается, когда адрес ушёл и вернулся.

Логин и пароль прокси панель не показывает и не отдаёт в Excel. Они хранятся только для проверки и в базе лежат в зашифрованном виде. Ключ задаётся в `MONITOR_SECRET`. Без него ключ создаётся в `data/.proxy-key` и по HTTP не отдаётся.

Повторная загрузка обновляет пароль и адрес у тех же `ip + port + login`. Галочка «удалить отсутствующих» убирает из списка то, чего нет в файле.
